An event is one thing a user did: viewed a page, added a product to the cart, completed a purchase. DAMA's reports look for specific **standard event names** and fields, so send those names exactly as written below. You can send any number of **custom events** on top of them.

## Prerequisites

- The [Web SDK](/setup/web) is installed, or you can send HTTP requests from your own code (see [Send events over HTTP](#send-events-over-http)). Mobile apps send over HTTP: see [iOS](/setup/ios), [Android](/setup/android) or [Flutter](/setup/flutter).

## Standard events

Event names are case-sensitive. Use them exactly as shown.

| Event | Send it when | Used by |
|---|---|---|
| `session_start` | A new session begins | **Retention Analysis**: a user's cohort is the period of their first `session_start`. |
| `page_view` | A page (or app screen) is viewed | **Dashboard** top pages; first step of the default **Funnel Analysis**. |
| `view_item_list` | A list of products is shown (category, search results) | Default **Funnel Analysis** step. |
| `view_item` | A product detail page is viewed | **Dashboard** top products; default **Funnel Analysis** step. |
| `add_to_cart` | A product is added to the cart | Default **Funnel Analysis** step; **Retention Analysis** engagement scoring. |
| `view_cart` | The cart is viewed | Default **Funnel Analysis** step; **Retention Analysis** engagement scoring. |
| `begin_checkout` | Checkout starts | Default **Funnel Analysis** step; **Retention Analysis** engagement scoring. |
| `purchase` | An order is completed | **RFM**, **cLTV**, **Dashboard** revenue, last step of the default **Funnel Analysis**, **Retention Analysis** engagement scoring. |

The default funnel runs `page_view` → `view_item_list` → `view_item` → `add_to_cart` → `view_cart` → `begin_checkout` → `purchase`.

### Session start

Retention Analysis builds its cohorts only from `session_start` events, so send one at the beginning of every session.

- **Web:** the Web SDK sends `page_view` automatically but **not** `session_start`. Add the snippet below.
- **Apps and HTTP:** send `session_start` yourself whenever you start a new session. The [iOS](/setup/ios), [Android](/setup/android) and [Flutter](/setup/flutter) examples show how.

The Web SDK keeps the current session in the `damadp_session_id` cookie, which expires after 30 minutes without activity. If that cookie is missing when the page starts loading, the SDK is about to start a new session. Check for it **before** the DAMA script tag, then send `session_start` right after it:

```html
<script>
  // Before the DAMA tag: no session cookie means this page load starts a new session.
  window.damaIsNewSession = !/(?:^|;\s*)damadp_session_id=/.test(document.cookie);
</script>
<script src="https://collect.example.com/sdk/dama.js?id=YOUR_ORGANIZATION_ID&token=YOUR_TRACKING_TOKEN&collect=https://collect.example.com"></script>
<script>
  // After the DAMA tag, once the page's HTML has been parsed (see "When to call damaDP" on the Web page).
  document.addEventListener('DOMContentLoaded', function () {
    if (window.damaIsNewSession) {
      damaDP('event', 'session_start');
    }
  });
</script>
```

The SDK queues the call and sends it as soon as it has started.

In Google Tag Manager, the first part must run before the DAMA tag and the last part after it. Use tag sequencing: put the cookie check in a Custom HTML tag set to fire **before** the DAMA tag, and `damaDP('event', 'session_start')` (inside the same `if`, without the `DOMContentLoaded` wrapper) in a Custom HTML tag set to fire **after** the DAMA tag.

The SDK also starts a new session without a page load when a tab comes back after more than 30 minutes in the background. The snippet covers sessions that start with a page load.

### Purchase: value and currency

Revenue figures in DAMA come from two fields of `purchase`:

- **Value**: the total order amount, as a number of zero or more. With the Web SDK, pass it as `value`. Over HTTP, send it as `event_cart_value`.
- **Currency**: a three-letter ISO 4217 code such as `TRY`, `USD`, `EUR` or `GBP`. With the Web SDK, pass it as `currency`. Over HTTP, send it as `event_currency`.

Dashboard revenue converts each purchase into your reporting currency using that day's exchange rate. DAMA converts **TRY, USD, EUR and GBP**. RFM and cLTV add up purchase values as they are sent, without converting them, so send all purchases of one app in the same currency.

<Warning>
A currency that isn't exactly three characters (for example `TL` or `₺`) makes the whole event fail validation, and it is not stored. Always send the ISO code.
</Warning>

### Examples

<CodeGroup>
```javascript Web
// Product list (category page, search results)
damaDP('view_item_list', {
  item_list_name: 'Running Shoes',
  items: [
    { item_id: 'SKU-123', item_name: 'Running Shoe', price: 1499.9 },
    { item_id: 'SKU-456', item_name: 'Trail Shoe', price: 1899.9 }
  ]
});

// Product detail page
damaDP('view_item', {
  value: 1499.9,
  currency: 'TRY',
  items: [{ item_id: 'SKU-123', item_name: 'Running Shoe', item_brand: 'Acme', item_category: 'Shoes', price: 1499.9 }]
});

// Add to cart
damaDP('add_to_cart', {
  value: 1499.9,
  currency: 'TRY',
  items: [{ item_id: 'SKU-123', item_name: 'Running Shoe', price: 1499.9, quantity: 1 }]
});

// Cart page
damaDP('view_cart', {
  value: 2999.8,
  currency: 'TRY',
  items: [{ item_id: 'SKU-123', item_name: 'Running Shoe', price: 1499.9, quantity: 2 }]
});

// Checkout started
damaDP('begin_checkout', {
  value: 2999.8,
  currency: 'TRY',
  items: [{ item_id: 'SKU-123', item_name: 'Running Shoe', price: 1499.9, quantity: 2 }]
});

// Order completed
damaDP('purchase', {
  transaction_id: '100234',
  event_transaction_id: '100234',
  value: 2999.8,
  currency: 'TRY',
  items: [{ item_id: 'SKU-123', item_name: 'Running Shoe', price: 1499.9, quantity: 2 }]
});
```

```json HTTP (purchase)
{
  "event_name": "purchase",
  "event_time": 1760947200000,
  "event_id": "order-100234-purchase",
  "event_cart_value": 2999.8,
  "event_currency": "TRY",
  "event_transaction_id": "100234",
  "event_items": [
    { "item_id": "SKU-123", "item_name": "Running Shoe", "price": 1499.9, "quantity": 2 }
  ],
  "session_id": "1760947000",
  "session_start_time": 1760947000000,
  "session_cookie_id": "3f2b8c1e-5d4a-4f7b-9a63-2c1d0e8f7a51"
}
```
</CodeGroup>

<Note>
**How the Web SDK maps your parameters:** `value` becomes the event value (`event_cart_value`), `currency` becomes the event currency (`event_currency`), and `items` becomes the event's item list (`event_items`). Parameters whose names match an event field, such as `event_transaction_id` or `event_category`, fill that field. Every other parameter (for example `transaction_id` or `item_list_name`) is stored as a custom event parameter.
</Note>

## Custom events

Any name that isn't a standard event is a custom event. Use lowercase words joined by underscores, such as `newsletter_signup` or `video_complete`. Custom events count toward the Dashboard **Events** chart.

<CodeGroup>
```javascript Web
damaDP('event', 'newsletter_signup', {
  form_location: 'footer',
  plan: 'weekly'
});

// Shorthand: an unrecognized command is sent as a custom event.
// Use the 'event' form above if the call can run before the SDK has started.
damaDP('newsletter_signup', { form_location: 'footer' });
```

```json HTTP
{
  "event_name": "newsletter_signup",
  "event_time": 1760947200000,
  "tracking_data": {
    "event_data": { "form_location": "footer", "plan": "weekly" }
  }
}
```
</CodeGroup>

**Rules for custom parameters**

- At most 40 parameters per event. Parameter names may contain only letters, digits, `_` and `-`, up to 128 characters.
- Values can be strings (up to 1,024 characters), numbers, booleans or null, a flat object of such values, or a list of up to 100 such values or flat objects.
- Never send plaintext personal data. Parameter keys such as `user_email`, `user_phone`, `user_name`, `user_first_name` and `user_last_name` make the event fail validation. Text that looks like an email address or an international phone number is replaced with `[redacted]` in event names, page and referrer fields, UTM fields, items and parameters.

If an event breaks one of these rules, the whole event is rejected and not stored.

## Send events over HTTP

If no SDK fits your platform, or you want to send events from your server, post each event as JSON to your collection URL. Send one event per request.

```bash
curl -X POST "https://collect.example.com/tracking/YOUR_ORGANIZATION_ID" \
  -H "Authorization: YOUR_TRACKING_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "event_name": "purchase",
    "event_time": 1760947200000,
    "event_id": "order-100234-purchase",
    "event_cart_value": 2999.8,
    "event_currency": "TRY",
    "event_transaction_id": "100234",
    "event_items": [
      { "item_id": "SKU-123", "item_name": "Running Shoe", "price": 1499.9, "quantity": 2 }
    ],
    "session_id": "1760947000",
    "session_start_time": 1760947000000,
    "user_email_hash": "e233d4a29013e9d87150c6237c6777bedf379ebf1acdc5d6126fec7e8bb74fb5",
    "identity_hash_version": "v1"
  }'
```

Replace `https://collect.example.com` with your collection URL (provided by DAMA during onboarding). The **Organization ID** and **Tracking Token** are on **Integration → SDK** in the DAMA panel. A successful request returns HTTP `202` with `{"success": true}`. The endpoint is also described in the [API reference](/api-reference/track-event).

For sessions and the Dashboard to work, send `session_id` and `session_start_time` on every event. To keep a device's anonymous activity together, send a stable device ID as `session_cookie_id` (see [Identify users](/setup/identify-users)).

### Field reference

Every field except `event_name` and `event_time` is optional. Any field not listed here, for example `user_id`, `user_email` or `session_ip`, is rejected, and the whole request fails with `422`. Text fields accept up to 1,024 characters unless a lower limit is listed.

<ParamField path="organization_id" type="string" required>
  Your Organization ID, in the URL path (8–64 characters: hexadecimal digits and `-`). If you also send `organization_id` in the body, it must match.
</ParamField>

<ParamField header="Authorization" type="string" required>
  Your tracking token, as the raw header value (no `Bearer` prefix).
</ParamField>

#### Event

<ParamField body="event_name" type="string" required>
  Event name, 1–128 characters. Use a [standard event](#standard-events) name where one applies.
</ParamField>
<ParamField body="event_time" type="integer" required>
  When the event happened, as a Unix timestamp in milliseconds. Values below 100,000,000,000 are treated as seconds and converted. It must be no earlier than 1 January 2020 and no more than 24 hours in the future.
</ParamField>
<ParamField body="event_id" type="string">
  Your unique ID for this event, up to 64 characters. If it is 8–64 characters of letters, digits, `_` and `-`, DAMA stores the event only once per ID (case-insensitive), so retries are safe. Without a usable `event_id`, DAMA treats events with the same user, `event_time`, `event_name` and `custom` values as duplicates.
</ParamField>
<ParamField body="event_cart_value" type="number">
  Event value (order total for `purchase`), zero or more. `event_value` is accepted as an alias.
</ParamField>
<ParamField body="event_currency" type="string">
  Three-letter ISO 4217 currency code, for example `TRY`. Stored in upper case.
</ParamField>
<ParamField body="event_transaction_id" type="string">
  Order or transaction ID, up to 128 characters.
</ParamField>
<ParamField body="event_qty" type="integer">
  Quantity, zero or more.
</ParamField>
<ParamField body="event_category" type="string">
  Free-form event category, up to 128 characters.
</ParamField>
<ParamField body="event_page_url" type="string">
  Full URL of the page.
</ParamField>
<ParamField body="event_page_path" type="string">
  Page path, for example `/products/running-shoe`. The Dashboard's top pages and top products are grouped by this field.
</ParamField>
<ParamField body="event_page_title" type="string">
  Page or screen title.
</ParamField>
<ParamField body="event_referrer" type="string">
  Referring URL.
</ParamField>
<ParamField body="event_source" type="string">
  Traffic source for this event, up to 256 characters.
</ParamField>
<ParamField body="event_medium" type="string">
  Traffic medium for this event, up to 256 characters.
</ParamField>
<ParamField body="event_campaign" type="string">
  Campaign for this event, up to 256 characters.
</ParamField>
<ParamField body="event_items" type="object[]">
  Products in the event, at most 100. Each item is a flat object with at most 20 keys (letters, digits, `_` and `-`). Values can be strings (up to 512 characters), numbers, booleans or null. Common keys: `item_id`, `item_name`, `item_brand`, `item_category`, `item_variant`, `price`, `quantity`. Items sent with `page_view` are not stored.
</ParamField>
<ParamField body="tracking_data" type="object">
  Your own event parameters, nested at most three levels deep, with at most 40 keys per object and 100 entries per list. Follows the [custom parameter rules](#custom-events). The Web SDK puts custom parameters in `tracking_data.event_data`.
</ParamField>
<ParamField body="custom" type="object">
  Flat key/value parameters (strings, numbers, booleans or null), at most 40 keys.
</ParamField>

### Responses

Every response is JSON. On error the body is `{"success": false, "error": "<code>"}`; it does not say which field failed.

| Status | Body `error` | Meaning |
|---|---|---|
| `202` | (none, `success: true`) | Accepted. |
| `401` | `ERR_AUTH_REQUIRED` | The `Authorization` header is missing. |
| `401` | `ERR_AUTH_FAILED` | The token is invalid or doesn't belong to the Organization ID in the URL. |
| `413` | `ERR_PAYLOAD_TOO_LARGE` | The body is larger than 32 KB (32,768 bytes). |
| `422` | `ERR_VALIDATION` | The Organization ID in the URL is malformed, or a field is invalid or not allowed. Nothing from the request is stored. |
| `422` | `ERR_ORGANIZATION_MISMATCH` | The `organization_id` in the body doesn't match the URL. |
| `429` | `ERR_RATE_LIMITED` | DAMA is limiting requests for this organization. Retry later. |
| `503` | `ERR_BUFFER_FULL` / `ERR_BUFFER_UNAVAILABLE` | Temporarily unavailable. Retry with backoff, and reuse the same `event_id` so retries never create duplicates. |

Don't retry `401`, `413` or `422` without fixing the request first.
