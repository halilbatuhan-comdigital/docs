<Info>
DAMA does not offer a native iOS SDK yet. You track an iOS app by sending events from your own Swift code over HTTP, or from Dart if the app is built with Flutter.
</Info>

## Prerequisites

- The iOS app of your company in DAMA. Its **Organization ID** is under **Integration → SDK → iOS** in the DAMA panel, where you can also save the app's **App ID** and **Bundle Name**.
- Your **Tracking Token**, shown next to the **Organization ID** on the same tab. If you don't see **Tracking Token** there, ask your DAMA contact for it.
- Your collection URL, provided by DAMA during onboarding. The examples use `https://collect.example.com`.

## Option 1: Flutter apps

If your iOS app is built with Flutter, track it from your Dart code. The [Flutter](/setup/flutter) page shows how to send events from Dart with your iOS app's credentials.

## Option 2: Send events over HTTP

Post each event as JSON to `https://collect.example.com/tracking/YOUR_ORGANIZATION_ID` (your collection URL, then `/tracking/` and your Organization ID) with your tracking token in the `Authorization` header. A successful request returns `202`. The [field reference](/setup/send-events#field-reference) lists every accepted field. Only `event_name` and `event_time` are required.

```swift
import CryptoKit
import Foundation

struct DamaClient {
    let endpoint = URL(string: "https://collect.example.com/tracking/YOUR_ORGANIZATION_ID")!
    let token = "YOUR_TRACKING_TOKEN"

    func send(_ event: [String: Any]) async throws {
        var request = URLRequest(url: endpoint)
        request.httpMethod = "POST"
        request.setValue(token, forHTTPHeaderField: "Authorization")
        request.setValue("application/json", forHTTPHeaderField: "Content-Type")
        request.httpBody = try JSONSerialization.data(withJSONObject: event)
        let (_, response) = try await URLSession.shared.data(for: request)
        guard (response as? HTTPURLResponse)?.statusCode == 202 else {
            throw URLError(.badServerResponse)
        }
    }
}

func sha256Hex(_ value: String) -> String {
    SHA256.hash(data: Data(value.utf8)).map { String(format: "%02x", $0) }.joined()
}

// A stable device ID, created once and stored
let deviceId: String = {
    if let saved = UserDefaults.standard.string(forKey: "dama_device_id") { return saved }
    let created = UUID().uuidString
    UserDefaults.standard.set(created, forKey: "dama_device_id")
    return created
}()

// Example: purchase by a signed-in user
let email = "customer@example.com".trimmingCharacters(in: .whitespacesAndNewlines).lowercased()
try await DamaClient().send([
    "event_name": "purchase",
    "event_time": Int(Date().timeIntervalSince1970 * 1000),
    "event_id": UUID().uuidString, // reuse the same value when retrying
    "event_cart_value": 2999.8,
    "event_currency": "TRY",
    "event_transaction_id": "100234",
    "session_id": "YOUR_SESSION_ID",
    "session_start_time": 1760947000000,
    "session_cookie_id": deviceId,
    "session_is_mobile": true,
    "user_email_hash": sha256Hex(email),
    "identity_hash_version": "v1"
])
```

When you send events yourself, you are responsible for the things an SDK would normally do:

- **Device ID:** create a random ID (a UUID works) on first launch, store it, and send it as `session_cookie_id` on every event. DAMA groups the device's anonymous activity by it and attaches that activity to the customer after they sign in.
- **Sessions:** create a session ID and start time, send them as `session_id` and `session_start_time` on every event, and send a `session_start` event when a new session begins (Retention Analysis needs it). We recommend the rule the Web SDK uses: start a new session after 30 minutes without events.
- **Screens:** send `page_view` (with `event_page_path` and `event_page_title`) for the screens you want in the Dashboard and Funnel Analysis.
- **Identity:** after login, send the SHA-256 hash of the normalized email as `user_email_hash`. Never send plaintext email, phone or name. On logout, stop sending the hash. See [Identify users](/setup/identify-users).
- **Consent:** send the user's consent choices as a string in `session_dcp`, for example `"[true,true,false]"` (essential, ads, analytics). Google Ads audience uploads need a granted ads choice. See [Consent](/setup/identify-users#consent).
- **Retries:** on a network error, `429` or `503`, retry with the same body. Because it keeps the same `event_id`, the event is stored only once. Don't retry `401`, `413` or `422`. See [Responses](/setup/send-events#responses).
